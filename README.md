# 匿名客流探头的授权切换与可撤回汇总

商场匿名通行探头、边缘计数与分区客流发布联调。目录中的记录为本地合成联调资料，
**不含任何可识别人身身份的信息**。

- `data/site.json` 保存现场配置及设备消息各类型的字段顺序。
- `data/frames.jsonl` 保存不同设备和工作人员提交的消息，逐行解码。

`arrival` 是资料中的接收序号，`captured` 是来源记录的现场时刻，单位为秒。`received` 是边缘收到消息的时刻，使用同一时间单位。设备补送仍携带原现场时刻。`source` 表示消息来源，`type` 是消息名称，`args` 按现场配置列出的顺序给出原值。每行记录一次接收，包括重复消息。设备此时的状态应按对应设备协议解释。

有限窗配对值是模拟设备提供给本次数据交换的短标记，配对到期后不作为持久索引。采集回报记录设备实际生效授权版本。检测方向用于通道归并。区段/商户的共享撤回事件与设备停止采集的回报分开。

## 边缘服务 `mall_edge/`

在资料之上实现的商场边缘服务，只产出**分区级匿名客流**，接收三类输入：
探头的匿名通行片段、运营的有效区段声明、楼层运营人员的发布与共享撤回操作。

| 模块 | 职责 |
| --- | --- |
| `mall_edge/model.py` | 授权、设备确认、经过、审计、发布期号等领域模型（无身份/无标记字段） |
| `mall_edge/ingest.py` | 片段授权核验、有限窗配对、到期清扫、重放幂等与无权片段审计 |
| `mall_edge/aggregation.py` | 覆盖评估、发布门槛、撤回重算、影响面与「可相减」防护 |
| `mall_edge/service.py` | 帧分发门面、终端查询/缓存语义、引导分区客流、值班追查、探头停止三项核定 |
| `mall_edge/replay.py` | 按接收顺序回放 `frames.jsonl` 驱动服务 |
| `demo_edge.py` | 回放并输出隐私合规视角的中文处置报告 |

### 隐私与数据最小化边界

- 配对标记只在内存待配对表中存活，寿命 = 边缘首次接收 + `join_signal_ttl_s`；
  配对解析或到期后立即销毁，**不写盘、不作为持久索引、不可重新导入**。
- 到期后到达的另一侧片段（含探头重启后的补送）一律以 `token_expired` 拒绝，
  无权参与去重；重放的同一观测以非识别性元数据幂等忽略，绝不重复计数。
- 无权片段不落任何观测数据，只写一条不含载荷与标记的处置审计。
- 持久对象只有聚合后的「经过」（设备、窗口、方向、授权版本），无标记、无人身身份；
  `test_no_token_or_identity_in_retained_objects` 对全量输出做标记泄漏扫描。

### 发布与撤回规则

核定顺序，任一不通过即暂缺且**数值不出服务**：
时间粒度 → 请求方共享资格 → 覆盖门槛 → 最低汇总人数 → 撤回后的可相减防护。

- **低覆盖不等于无人经过**：`partial/down` 区段不发布零值，可确证独立经过仍保留供追查。
- 一个通道只允许一侧采集时，该侧可证实的独立通行继续可用；对侧无权片段不参与去重。
- 片段归属以**采集当时**的区段、设备启用资格与设备确认的授权版本为准，后续版本切换不溯及。
- 商户可在授权时段内统计、可临时撤回；撤回按区段精确传播，其他区段/楼层的合法窗口不停用。
- 同一统计窗曾能看到旧汇总的终端全部计入影响面；门店端断线副本在 `client_cache_s`
  期限内可读，但**撤回可知即失效**，不以 TTL 未到为由继续提供。
- 撤回后重算若仍达发布门槛、但与旧版计数不同，对同时见过两版的对象触发可相减防护，
  不提供可反推被撤通行的新数。

### 探头停止的三项分别核定（`assess_device_stop`）

1. **是否确认停止**：以设备回报的 `off` 为准；仅链路离线不等于确认停止（可能仍在缓冲）。
2. **旧数据能否按原授权使用**：撤回前采集、归属当时授权版本的可确证经过仍可在原授权
   目的与保留期限内使用；撤回不溯及采集本身。
3. **原发布是否仍合规**：已发布期号若因撤回失效则置 `withdrawn` 并通知影响终端；
   覆盖/隐私门槛导致从未发布的窗口不属于「原发布」，不与发布不合规混为一谈。

### 角色接口

- 引导人员 `guidance_zone_flow`：仅分区级当前有效客流，无来源明细。
- 商户/门店端 `terminal_query`：本商户授权范围内的有效汇总，含断线副本失效语义。
- 楼层运营 `publish`/`share` 帧：核定某期该不该发、登记共享撤回/恢复。
- 值班人员 `trace_window`：追查覆盖/撤回/隐私门槛暂缺原因，只显示仍合法保留的来源与
  范围依据（授权窗口、商户共享状态、被拒观测的依据）。

## 运行

Python 3.11 标准库，无需网络或外部设备。

```text
# 原始资料逐帧回放（既有）
python3 device_replay.py

# 边缘服务处置报告
python3 demo_edge.py

# 完整测试（普通模式）
python3 -m unittest discover -s tests -v

# 完整测试（隔离模式，不读 PYTHONPATH/环境变量、不自动加载站点模块）
python3 -I run_tests.py
```

`run_tests.py` 显式注入项目根路径，因此在隔离模式与任意工作目录下都能定位本项目模块；
读取不可信资料目录时建议始终配合 `-I`，避免目录内被植入的同名模块被解释器加载。
